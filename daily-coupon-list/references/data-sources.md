# 券数据从哪来

`minpay.py` 只做计算，不做抓取。它要的是一份符合下面「标准结构」的 JSON。
获取方式按优先级排两条路，能走 A 就走 A，否则走 B。

> **⚠️ 能自动领券的只有美团。** 路径 A 目前只有美团走得通 ——
> 其他平台（淘宝闪购、京东外卖、饿了么、打车团购等）没有可编程的领取接口，
> 它们的领券入口是活动 H5 页面，本技能**不去爬**，一律走路径 B 让用户手动提供。
> 计算部分对来源平台没有要求，字段对得上就能算。

---

## 标准结构

`minpay.py` 认这三种外层形态，任选其一：

```json
{ "coupons": [ ... ] }
```

```json
{ "data": [ ... ] }
```

```json
[ ... ]
```

数组里每张券按下列字段解释：

| 字段 | 别名 | 单位 | 说明 |
| --- | --- | --- | --- |
| `name` | `title` | — | 券名 |
| `discount_info` | `discountInfo` | — | 券面说明，如「满20元减14元」；缺失时会由门槛和面额自动补 |
| `priceLimit` | `limit` `threshold` `minSpend` | **分** | 使用门槛 |
| `couponValue` | `value` `discount` `amount` | **分** | 券面额 |
| `tabName` | `tab` `category` | — | 品类 |
| `valid_period` | `validPeriod` `expire` | — | 有效期 |

> **单位是最大的坑。** 默认按「分」解释（`--unit cent`）。如果你的数据本来就是元，
> 必须显式加 `--unit yuan`，否则会算出一堆 100 倍的数字。

## 路径 A：本机已有能返回结构化券数据的工具（自动领券，目前仅美团）

如果当前环境里已经装了某个能给出**券的门槛、面额、品类**的工具或连接器，优先用它，
把返回的 JSON 落盘后直接喂给 `minpay.py`。

链路要求只有两点：

1. 能拿到**每张券的 `priceLimit` 与 `couponValue`**（这两个数字是全部计算的基础）；
2. 输出能落成 JSON 文件（不要只取屏幕上的自然语言文案）。

### 已知可用：美团官方助手（目前唯一能自动领券的一条路）

美团官方提供的助手类能力 `MeituanLivingAssistant`，其命令入口会返回如下结构，可直接使用：

```json
{
  "ok": false,
  "code": 1014,
  "message": "您今天已经领取过优惠券",
  "coupon_count": 56,
  "coupons": [
    { "name": "玩乐变美1元券", "discount_info": "", "valid_period": "2026-09-19 至 2026-09-26",
      "priceLimit": 0, "couponValue": 100, "tabName": "丽人医疗" }
  ]
}
```

拿这份数据时要绕开三个坑，全部实测踩过：

1. **`code` 非 0 不等于失败。** 当天重复调用会返回类似 `1014`、
   「您今天已经领取过优惠券」，但 **`coupons[]` 照旧齐全**，直接解析即可，不要报成"领券失败"。
2. **金额单位是分。** 上面 `couponValue: 100` 是 1 元，不是 100 元。
3. **Windows 下中文会乱码。** 直接捕获命令行 stdout 可能被按 GBK 解码成 `鐜╀箰...`。
   稳妥做法是重定向落盘再用 UTF-8 读文件，而不是直接读管道。

### 其他平台：没有这条路

淘宝闪购、京东外卖、饿了么、打车/团购类目前**只有人工点击的领券入口**（网页或小程序活动页），
没有返回结构化券数据的接口，因此：

- **不要去爬页面。** 这类活动 H5 改版频繁，爬虫要反复重写；而且登录态一失效，
  返回的券数会悄悄变少，用户拿到的是一份看起来正常、实际上缺券的清单 —— 比没有更糟。
- **不要伪造券数据。** 拿不到就直说「这个平台暂时只能手动」，然后走路径 B。

如果哪天某个平台推出了官方接口，直接在路径 A 加一节即可，计算层不用动。

## 路径 B：让用户自己提供（其他平台，或本机没有对应工具时）

没有可用工具时，请用户提供券信息，任何形式都行：

- **粘贴文本**：把券列表复制出来，你负责转成标准 JSON；
- **截图**：读图后逐张提取券名、门槛、面额、品类、有效期；
- **平台导出的 JSON / CSV**：字段名对得上就直接用，对不上就做一次字段映射。

转换时的纪律：

- **只填看得到的东西。** 门槛或面额没看清的，该张券 `limit` / `value` 留空，
  `minpay.py` 会把它归入「字段缺失」区，**不要推测、不要按同名列的常见值补齐**。
- 券名照抄，不要润色成「XX 平台超值神券」这类你自己造的名字。

---

## 不要打进发布包的东西

发布到公开市场前，确认包里**没有**下列内容：

- 任何 API Key、Token、Cookie、登录凭证；
- 带分佣参数的推广短链（`uid=` / `childId=` 之类）；
- 你个人的账号 ID、设备标识。

本技能的 `scripts/` 只做本地计算与本地记录，不发起任何网络请求。

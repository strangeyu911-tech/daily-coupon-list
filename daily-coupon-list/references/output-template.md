# 输出模板与措辞要求

`minpay.py` 已经能直接吐出成品 Markdown，正常情况下**原样转发即可**。
这份文件用于两种情况：脚本没跑（数据量很小、手算更快），或需要手工调整措辞。

---

## 骨架

```markdown
## 每日领券省钱清单

共解析 N 张券。最低实付 = 使用门槛 − 券面额，是**理论下限**，具体商品价格请在平台 App 内看。

### A 组 · 低门槛券（使用门槛 < 5 元）
<表格；为空时写：今日没有使用门槛低于 5 元的券。这是平台定价策略，不是获取失败。>

### B 组 · 近白嫖券（门槛 ≥ 5 元，且最低实付 < 1 元）
<表格；为 0 张时列门槛达标且最低实付最接近的 2 张，并写明这是 0 张>

### 实物专区（能买到实物或餐食的品类）
<表格>

### C 组 · 其余品类（按品类汇总）
| 品类 | 张数 | 最低实付区间 | 门槛最低的一档 |

> 说明：最低实付是「买一件价格刚好等于门槛的商品」时的实付下限，不代表平台上一定存在该价格的商品；
> 券的可用范围、有效期与最终抵扣以平台 App 内结算页为准。
```

单张券的表格固定 7 列：券名 / 品类 / 券面说明 / 使用门槛 / 券面额 / 最低实付 / 有效期。

---

## 措辞纪律（重要）

**1. 必须说清楚「理论下限」。**
`最低实付` 的意思是"如果平台上存在一件价格刚好等于门槛的商品，你要付多少"。
它**不是**"现在就能花这个价买到东西"。凡是给出最低实付的地方，都要挨着这句限定。

**2. 没有就是没有，不凑数。**
A 组 0 张、B 组 0 张是常态 —— 门槛 < 5 元的券每天通常只有一到两张，
主流券的门槛集中在 20 到 45 元。这是平台定价策略，不是抓取失败，要如实说。

**3. 未返回的字段写「未返回」。**
不猜、不补、不用同类券的值顶替。

**4. 品类不能混用。**
只有实物类（可买到实物或餐食的品类）的券才谈得上"低价买实物"；
到店餐饮类的券门槛通常**远高于**单件商品价，结果是"一张券都用不上，券后价 = 原价"——
这是结构性事实，直说，不要硬套不适用的券去制造"券后价"。

**5. 不夸大平台。**
不写「全网最低」「必胜」这类无法证实的断言；不承诺一定能领到、一定省多少。

---

## 一句话结论怎么写

在清单**最前面**加一句结论，让用户不翻表格也能用：

- 有 A 组券时：「今天有 N 张低门槛券，其中 X 张最低实付 0 元，可以优先看。」
- A 组为空时：「今天门槛最低的券是「<券名>」（门槛 M 元），低于 5 元的券没有。」
- 全部不可用时：「今天没有能用得上的券，原因是 <门槛普遍高于你的目标价位>。」

结论里的每个数字都要能在下面的表格里对上，不要出现表格里没有的数字。
